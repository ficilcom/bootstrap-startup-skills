# インテークと公式根拠

この資料は、探索・適合評価の前に、対象を定め、資料と現在の公式情報を追跡可能にするためのものです。制度の有無や条件を記憶・検索結果の抜粋・民間の要約で決めず、判断に使う事実は現行の公式一次情報へ戻ります。

## 対象プロフィールと資料台帳

利用者が提出した資料を先に読み、次だけを必要な範囲で整理します。

| 項目 | 確認する内容 | 根拠例 |
| --- | --- | --- |
| 対象主体 | 法人・個人、登記上または事業所の所在地、代表的な拠点 | 登記事項、開業届、利用者説明 |
| 事業と規模 | 業種、従業員数、資本金、売上等の該当する定義 | 決算書、労働者名簿の集計、利用者説明 |
| 時間軸 | 設立日・開業日、着手済みの行為、支出・契約・納品予定日 | 登記、契約、請求書、見積 |
| 計画 | 実施する事業、成果物、対象経費、総額、必要資金時期 | 事業計画、見積、予算 |
| 資金負担 | 自己資金、借入、立替可能額、資金繰り上の制約 | 残高の要約、資金繰り、利用者説明 |
| 制約 | 他制度の受給・申請、過去受給、許認可、共同申請者 | 交付決定通知、申請控え、許認可、利用者説明 |

資料台帳には、資料名、対象主体、対象期間または作成日、関連する項目、必要箇所の要約、情報区分を残します。原本や不要な機微情報を複製しません。

## 情報区分

条件の評価状態とは別に、個々の事実を次で区分します。

| 情報区分 | 意味 | 扱い |
| --- | --- | --- |
| `official_current` | 確認日現在の制度運営者による公式ページ、当該回の公募要領、公式FAQ等 | URL、確認日、版・改定日、要約を残す |
| `official_historical` | 公式だが、対象回・有効性・改定状況を現時点で確認できない資料 | 現行要件の証拠にしない |
| `documented` | 利用者の提出資料で確認できる事実 | 資料名・日付・参照箇所を残す |
| `reported` | 利用者または責任者の直接説明 | 未検証であることを残す |
| `derived` | 資料・制度条件からの計算または推論 | 式と仮定を残す |
| `unknown` | 利用できない、読めない、または確認できない情報 | 不適格やゼロに置き換えない |

`official_current` でも制度要件、応募者の事実、運営者裁量の判断は別物です。例えば、要件本文は `official_current` でも、対象者の従業員数が資料で確認できなければ、その条件の評価は `unclear` です。

## 現在の公式情報を確認する

制度を判断に使うたび、公式の募集ページから当該回の公募要領・別紙・申請手引き・公式FAQへ進みます。確認する優先順位は次のとおりです。

1. 制度運営者または所管官庁の当該回の募集ページと、受付中・終了・次回未定等の状態
2. 当該回の公募要領、交付要綱、募集案内、別紙の版番号または発行・改定日
3. 対象者、対象事業、対象経費、経費計上時期、申請前の契約・発注・支出の可否
4. 補助率、上限・下限、対象外経費、自己負担、立替、支払・実績報告・入金の仕組み
5. 申請締切、実施期間、併用・重複受給・過去受給、予算残・早期終了の扱い
6. 報告、証憑保存、検査・監査、財産処分、成果公表などの交付後義務
7. 定義や個別事情の判定が残る場合の公式問い合わせ先と受付時間・方法

公式ページへの検索結果は入口としてだけ使えます。URLが制度運営者かを確認し、リンク先の本文・公募要領を読んでから根拠にします。予算残や受付状況が公式に公開されていない場合は、`unknown` とし、推測や古い告知で補いません。募集終了・対象外・支出済みなどを示す現行の公式条件があれば、その条件だけ `ineligible` とできます。

## 根拠台帳

制度ごとに、引用の長文ではなく、次を簡潔に記録します。

| 項目 | 記録内容 |
| --- | --- |
| 確認日 | 情報を実際に読んだ日 |
| 発行者・資料名 | 運営者、募集ページ、公募要領、FAQ等の名称 |
| URL | 直接読んだ公式URL |
| 対象回・版 | 公募回、版番号、発行日・改定日。なければ「記載なし」 |
| 状態 | 受付中、終了、次回未定、または公式に状態不明 |
| 要約根拠 | 評価した条件に関係する内容を自分の言葉で要約 |
| 範囲・未解決 | 何が確認できず、どの窓口・資料で確認するか |

「当日」は、制度の変更可能性があるため、評価を作成する日を指します。過去に収集したURLを再利用する場合も、当日に開いて有効性・版・受付状態を再確認します。募集終了後に将来の公募を予測する結論は出さず、次回の公式公表を待つ旨を記します。

## 探索価値を判断する `explore`

候補制度がない段階では、特定制度への適格性を評価しません。次の問いで、公式情報を探索する価値を判断します。

- 資金使途、地域、対象主体、業種・規模、実施時期が明確で、制度探索の絞り込みに足りるか。
- 支出・契約・発注が既に済んでいる、または予定日が近く、事前承認型の制度に間に合わない可能性が高いか。
- 補助金が後払いでも、立替資金と対象外経費を負担できる見込みがあるか。
- 探索・書類収集・申請準備に割ける時間があり、本業の優先案件を損なわないか。
- 採択されなくても、事業計画、見積比較、予算、証憑管理、許認可確認の整備に独立した価値があるか。

結論は `探索を進める`、`情報をそろえてから探索`、`現時点では見送る` のいずれかとし、理由、探索範囲、止める条件を示します。例えば、支出前承認の成否が最重要なら、契約や支出を進める前に公式要領を確認することを優先します。ただし、支出・契約の停止や変更は提案にとどめ、利用者の明示承認なしに実行しません。
