# 典型カテゴリと必要な証跡

取引先のセキュリティチェックシートは書式が違っても、問われる領域はおおむね次に収まる。棚卸しはこのカテゴリ単位で行い、カテゴリごとにどの型の証跡が求められるかを確認する。

| カテゴリ | 典型的な設問 | 求められる証跡の型 |
| --- | --- | --- |
| アクセス管理 | 認証方式、多要素認証、権限付与と棚卸し、退職時の削除 | 設定画面の状態、権限一覧、棚卸し記録 |
| 端末管理 | 業務端末の指定、暗号化、資産台帳、私物端末の扱い | 設定画面の状態、台帳、規程 |
| 委託先管理 | 再委託の有無、委託先の選定基準、委託先との契約条項 | 契約書、委託先一覧、選定記録 |
| インシデント対応 | 検知方法、報告経路、報告期限、過去の発生有無 | 手順書、連絡体制図、対応記録 |
| バックアップと復旧 | 取得頻度、保管場所、復旧目標、復旧テストの実施 | 設定画面の状態、復旧テスト記録 |
| ログ管理 | 取得対象、保存期間、改ざん防止、確認の頻度 | 設定画面の状態、保存期間の設定、確認記録 |
| 教育と体制 | 実施頻度、対象者、責任者の任命 | 実施記録、受講者一覧、任命の記録 |
| 物理セキュリティ | 執務場所、入退室、書類と媒体の管理 | 規程、入退室記録 |
| 契約と法令 | 秘密保持、データの所在地、削除・返却、監査受入 | 契約書、データ配置の説明資料 |

## 証跡の型を見分ける

- **規程・手順書**: 定めがあることを示す。運用されている証明にはならないため、記録を伴う設問では単独で足りない。
- **設定画面の状態**: 現在そうなっていることを示す。日付入りのスクリーンショットまたは設定のエクスポートで残す。
- **ログ・記録**: 継続して運用されていることを示す。実施記録のない手順書は「部分的」として扱う。
- **第三者による証明**: 認証、監査報告、クラウド事業者の報告書。自社の統制と、事業者側の統制を混同しない。

## 小規模事業者で頻出のギャップ

- 規程はあるが実施記録がない（教育、権限棚卸し、復旧テスト）。
- クラウド事業者の統制を自社の統制として回答している。責任分界を確認する。
- 委託先・再委託先の一覧が最新化されていない。
- 退職・契約終了時のアカウント削除に手順と記録がない。
- ログは取得しているが保存期間が設問の要求より短い。
