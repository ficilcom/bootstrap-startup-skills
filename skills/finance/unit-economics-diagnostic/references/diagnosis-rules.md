# 診断ルールと感度の優先順位

スクリプトのフラグは非排他的であり、普遍的な点数ではない。必ず数値、証拠区分、対象期間、運営制約と一緒に解釈する。

## フラグ

### `negative_unit_economics`

単位限界利益がゼロ以下。売るほど固定費回収に寄与しない。価格、COGS、その他変動費の範囲と二重計上を先に確認し、正しい場合は数量拡大を好意的に評価しない。

### `acquisition_not_recovered`

選択CACを観測またはモデル化した顧客期間内に回収できない。観測コホートでは供給期間内未回収、固定期間・継続率一定では貢献LTVが選択CAC未満である。売上LTVで上書きしない。

### `unit_positive_but_cash_hungry`

単位限界利益は正で、信頼できる期間内にはCACを回収できるが、回収期間が利用者の `max_payback_periods` を超える。未回収とは区別し、成長時の先行資金需要を資金繰り分析へ引き継ぐ。

### `break_even_beyond_capacity`

損益分岐数量が入力された実行可能キャパを超える。価格・単位費用・固定費・キャパのどの制約が支配的かを示す。キャパ拡張が可能と推測しない。

### `profitable_to_scale`

次をすべて満たす場合だけ返る。

- 単位限界利益が正
- 損益分岐が既知キャパ内
- 選択CACの範囲が意思決定に必要な費用を含む
- 獲得費と顧客コホートが整合する
- 選択CACが信頼できるLTV期間内に回収される
- 回収期間目標が入力されている場合はその目標内

このフラグは、需要、販売可能性、運転資金、資金調達、実行能力、企業価値、会社全体の利益を保証しない。

### `positive_unit_economics_unassessed_acquisition`

単位限界利益は正だが、キャパ、選択CAC、費用範囲、コホート整合、LTV、または回収目標の証拠が不足し、拡大支持まで言えない。欠けた根拠を具体的に列挙する。

### `indeterminate`

価格、COGS、変動費など必要な単位入力が不明で、単位採算を判定できない。数値結論を作らず、最小の追加根拠と確認方法を示す。

## CACの解釈

選択基準以外のCACは比較材料であり、混ぜて平均しない。報告書では次を選択CACの隣に示す。

- 分子に含めた費用
- 分母の新規顧客定義
- 対象期間またはコホート
- 費用発生と顧客獲得の時間整合
- 固定費に同じプールが含まれるか
- `decision_cac_scope_complete` と `selected_pool_matches_customer_cohort`

計算できるCACでも、範囲不完全またはコホート不整合なら `profitable_to_scale` の根拠にしない。

## ベンチマークの扱い

「LTV:CACは3以上」「回収は12か月以内」のような一般値を合否判定として固定しない。チャネル、粗利、資金制約、成長速度、顧客リスクで意味が変わる。利用者が社内方針や契約上の目標を提示した場合だけ、その出所を `confirmed` または `reported` として比較する。

外部ベンチマークを求められた場合は、当日の信頼できる一次資料または明確な調査方法を使い、定義・対象業種・企業段階・期間の比較可能性を明示する。外部値を自社の合格基準へ自動適用しない。

## 感度の優先順位

次の順で、結論またはフラグを変え得る項目に絞る。

1. `unknown` または重要な `estimated` 入力
2. 単位限界利益を正負反転させる価格・COGS・変動費
3. キャパ内外を変える固定費・数量・キャパ
4. CAC回収可否や利用者目標を変える獲得費・顧客当たり数量
5. LTV回収可否を変える解約率、固定期間数量、コホート限界利益

最低価格、現在数量での損益分岐価格、許容変動費、目標回収期間に対する最大CAC、LTV=CACとなる最大解約率を、まずブレークポイントとして使う。範囲を無作為に大量生成しない。

感度ケースは元シナリオから独立させる。価格低下と原価上昇を同時に見たい場合は一つの明示的な複合ケースにし、別々のケースの差分を足して代用しない。

## 次の判断への接続

- 単位採算が負: コスト分類を確認後、価格・提供設計・変動費の選択肢をモデル化
- 採算は正だが未回収: チャネル、獲得費範囲、継続・再購入の根拠を確認
- cash hungry: 成長速度と獲得先行支出をキャッシュ・ランウェイへ接続
- キャパ超過: 提供能力、採用、外注、在庫、リードタイムの別分析へ接続
- scale支持: 需要、品質、キャッシュ、実行制約を別に確認してから実行判断

分析は提案までである。価格変更、広告停止・増額、採用、人員変更、契約・顧客条件変更、外部連絡、取引は、実行直前に利用者の明示承認を得る。
