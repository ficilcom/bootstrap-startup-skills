# 融資申請準備度診断の報告書契約

この形式は、スコアラーの JSON と、資料台帳・評価根拠・赤旗・未解決事項・融資ルートの所見を一つの日本語診断にするための契約です。見出しの順序を変えず、情報がない欄も「該当なし」または `unknown` の理由を簡潔に記す。未確認情報を悪い事実として書かず、確認済みの赤旗と未解決の質問を混在させない。

## 入力の対応

- スコアラー JSON の `final_score`、`raw_score`、`readiness_band`、`confidence_percent`、`provisional`、`criterion_points`、`missing_core_criteria`、`applied_cap` を転記・説明する。
- 各評価項目には、ルーブリックで用いた `rating`、`evidence`、短い根拠、評価理由を添える。情報区分は `confirmed`、`reported`、`inferred`、`unknown` のいずれかをそのまま記す。
- 赤旗には事実、情報区分、影響、解消または確認に必要な行動を付ける。`confirmed` または `reported` のみを重大懸念とし、`inferred` と `unknown` は未解決の重要確認事項に置く。

## 必須テンプレート

```markdown
# 融資申請準備度診断

## 診断概要
- 診断日: [日付]
- 診断モード: [startup / operating_company]
- 対象となる借入目的・希望額: [目的・金額・必要時期]
- 判定の前提: [対象主体、対象期間、利用資料、主な制約]

## 総合結果
- 総合判定: [readiness_band の日本語ラベル]
- 申請準備度（上限適用前）: [raw_score] / 100
- 申請準備度: [final_score] / 100（[readiness_band の日本語ラベル]）
- 診断確度: [confidence_percent]%
- 暫定判定: [はい / いいえ]
- 暫定の理由: [暫定の場合は、診断確度が60%未満か、missing_core_criteria の項目名と不足内容。暫定でない場合は該当なし]
- スコア上限: [applied_cap がある場合、上限値と適用した confirmed / reported 赤旗の事実・情報区分・影響。ない場合は「適用なし（raw_score と final_score は同じ）」]

## 項目別評価
| 項目 | 得点 / 配点 | 情報区分 | 主な根拠 | 評価理由 |
| --- | --- | --- | --- | --- |
| [criterion] | [criterion_points] / [weight] | [confirmed / reported / inferred / unknown] | [資料名・日付または説明] | [ルーブリックに照らした理由] |

## 強み
- [確認済みまたは申告済みの強みと根拠]

## 重大懸念
- [confirmed / reported の赤旗のみ。事実、情報区分、影響、必要な解消・説明]

## 未解決の重要確認事項
- [unknown / inferred の重要事項、確認質問、結論に与え得る影響]

## 優先改善アクション
| 優先度 | 対応 | 理由 | 完了の目安 |
| --- | --- | --- | --- |
| [高 / 中 / 低] | [具体的な準備または確認] | [準備度・赤旗・資料整合性への影響] | [確認できる完了条件] |

## 不足資料
- [資料名、対象期間、必要な理由。不要なら該当なし]

## 適合傾向のある融資ルート
- [ルート名: 適合傾向、根拠、強める資料、先に確認すべき現在の公式条件]

## 次の行動
1. [実務的な順序で、最初に行う行動]
2. [次に行う行動]
3. [必要なら、公式情報を確認してから相談・申請する行動]

## 注意事項
- この申請準備度スコアは申請準備の度合いを示すものであり、融資承認の確率を示すものではありません。
- 名称を挙げた制度の詳細は、必ず最新の公式情報で確認してください。
- 本診断は金融機関の審査、税務・法務・会計上の助言に代わるものではありません。必要に応じて専門家へ相談してください。
- 口座番号、個人番号、本人確認書類番号など不要な機微情報は報告書に記載しません。
```

## 表示ルール

`raw_score` は「申請準備度（上限適用前）」として `final_score` の直前に表示し、赤旗による上限適用前の基礎的な準備度を示す。`final_score` は「申請準備度」として表示し、`readiness_band` の日本語ラベルをすぐ隣に置く。`applied_cap` がないときは、スコア上限を「適用なし（raw_score と final_score は同じ）」と明記する。ラベルは、`ready` を「申請準備が進んでいる」、`conditionally_ready` を「条件を整えれば申請を検討できる」、`improvement_priority` を「申請前の改善を優先」、`significant_issues` を「重大な課題の解消を優先」とする。これは承認可能性の表現に置き換えない。

`provisional` が真なら、スコアの近くに「暫定」と表示し、`missing_core_criteria` の各項目と不足している資料・質問を隣接して示す。診断確度が60%未満で暫定の場合も、どの情報区分が不足しているかを簡潔に説明する。

`applied_cap` がある場合、該当する `confirmed` または `reported` の赤旗ごとに、観測した事実、情報区分、適用上限、解消アクションを「スコア上限」と「重大懸念」の両方で対応付ける。この場合は `raw_score` と `final_score` の差も読めるようにする。上限は自動否決を意味しない。`unknown` や `inferred` の懸念に上限を付けず、「未解決の重要確認事項」に置く。

優先改善アクションは、赤旗の解消、コア項目の不足、返済原資と資金使途の裏付け、資料の整合・更新という順に、実務上の依存関係も考慮して並べる。融資ルートは制度の断定ではなく傾向として書き、具体的な制度条件を求められたときは最新の公式情報を確認してから述べる。
