# 融資申請準備度の資料起点インテーク

このインテークは、採点に必要な `mode`、根拠の台帳、資料間の重要な不整合、各評価項目の根拠、未解決の確認事項を作るためのものです。提出済み資料を先に読み、資料で分かることを再質問しません。融資申込み、金融機関への連絡、信用情報の取得はこの診断には含まれません。

## 1. 対象範囲を確認する

最初に、事業と借入希望が日本に関係することを確認する。日本以外の法域、または複数法域を主対象とする案件は、この基準だけで結論を出さず、対象法域と必要な専門家確認を明示する。

確認する範囲は次のとおりです。

- 事業主体、事業所の所在地、業種、事業開始日（予定日を含む）
- 借入目的、希望額、資金が必要な時期、申込み予定の有無
- この診断で扱う主体・事業・期間、および利用できる資料
- これは申請前の準備度診断であり、承認見込みや金融機関の内部判断を予測しないこと

## 2. モードを選ぶ

事業開始日と完了した決算期の有無を使い、次のいずれかを明示する。

- `startup`: 開業前、または最初の決算期を完了していない事業
- `operating_company`: 少なくとも1期分の決算を完了している事業

法人設立日だけで判定しない。実際の事業開始日、決算期間、休眠・事業承継・大幅な事業転換の有無を確認する。開始日または完了決算期が分からなければ、これら二点だけを質問して採点を保留する。両方の見方が有用な移行案件でも、スコアは一つのモードでのみ算定し、選択理由ともう一方の観点を注記する。

## 3. 共通の資料台帳を作る

受領資料ごとに、資料名、対象主体、対象期間または作成日、作成者、要点、関連する評価項目、情報区分を記録する。原本全体を複製せず、評価に必要な要約とページ・行・日付などの追跡可能な参照を残す。

共通して確認する資料・情報は次のとおりです。

- 事業概要、借入目的、希望額、資金使途、必要時期、申込み先が決まっていればその範囲
- 主たる顧客・供給先・契約、売上や受注の根拠、必要な許認可
- 既存借入、リース、保証、返済予定、担保・保証人に関する本人の任意開示
- 税務・社会保険の申告・納付状況、係争・規制上の重要事項（該当する範囲）
- 事業計画、資金繰り見通し、前提となる見積・契約・計算書

根拠は必ず次のいずれかに分類する。

| 情報区分 | 扱い |
| --- | --- |
| `confirmed` | 提出資料で裏付けられた事実。資料名・日付・参照箇所を記録する。 |
| `reported` | 申請者または責任者の直接説明。未検証であることを残す。 |
| `inferred` | 資料や説明から行った計算・推論。計算式・仮定を示す。 |
| `unknown` | 利用できない、読めない、または確認できない情報。悪い事実としては書かない。 |

各モードのルーブリックに渡す際は、全評価項目について、`rating`、`evidence`、短い根拠、評価理由をそろえる。確認済みまたは申告済みの重大懸念だけを赤旗候補として分離し、`unknown` と `inferred` の懸念は未解決の確認事項に残す。

## 4. スタートアップで集めるものと聞くこと

資料は、入手できるものから次を確認する。

- 創業計画書または事業計画、商品・顧客・販売方法・運営体制の説明
- 創業者と主要担当者の職歴、業界経験、資格、役割分担
- 資金調達・資金使途表、自己資金の出所と投入時期、材料となる見積書・契約書
- 月次の売上・原価・経費・税金・生活費（該当時）・既存返済・新規返済を含む予測と下振れ想定
- 既存債務・リース等の明細、必要な許認可、該当時の税・社会保険の状況

資料から判断できない場合だけ、次のような評価を変え得る質問を行う。

- 希望額の各使途、支払先、支払時期、見積または計算根拠は何か。資金源の合計と使途の合計は一致するか。
- 売上予測の顧客数、単価、開始時期、根拠は何か。低調な場合でも返済後に残る現金はどの程度か。
- 創業者の経験・資格の不足を誰がどのように補うか。営業・供給・許認可の開始条件は満たせるか。
- 開示可能な範囲で、既存債務、税・社会保険、許認可、重大な法的・規制上の問題に未解決事項はあるか。

個人信用情報、口座番号、マイナンバー、身分証番号は要求しない。返済履歴等は本人が任意に開示する範囲に限り、必要な結論だけを記録する。

## 5. 事業継続会社で集めるものと聞くこと

入手できる範囲で、最大3期分の完了決算、直近試算表、現預金・資金繰り表または銀行入出金の要約、債務返済予定表、税務申告書を確認する。売掛金または在庫が重要なら年齢表・明細も確認する。あわせて、借入使途の見積・契約・計算根拠、現時点の予測、重要な顧客・受注・契約・許認可の情報を集める。

資料から判断できない場合だけ、次を確認する。

- 売上・利益・現金残高の主要な増減、一次的損益、関係者取引、季節資金需要は何か。
- 既存借入と希望借入を含む返済額は、どの現金創出と資金繰りで支えるか。下振れ時の対応は何か。
- 主要売掛金・在庫・顧客集中・供給依存に、回収不能、陳腐化、解約などの重要な変化はあるか。
- 希望額、使途、支払時期、資産耐用期間との関係、代替資金の検討は明確か。
- 税・社会保険、既存借入条件、許認可、重要な法的・規制上の事項に、開示できる未解決問題はあるか。

数値を抜き出す際は、単位、税込・税抜、対象期間、連結・単体、発生主義・現金主義の差を記録する。資料が読めない場合は資料名と原因を示し、読めた資料だけで暫定評価を続ける。

## 6. 不整合と機微情報を扱う

重要な不整合は、資料・説明のどこが、どの期間・単位・前提で食い違うかを中立に記録する。より有利な数値を選ばず、両方を示して説明または照合資料を求める。説明で解消していなければ、`confirmed` または `reported` の事実として赤旗の要件を満たすかを確認し、満たさない懸念は未解決事項とする。

収集・報告する情報は必要最小限にする。口座番号、個人番号、住所、生年月日、本人確認書類の画像、詳細な個人信用情報、不要な取引先個人情報は伏せるか要約する。原資料へのアクセス、保存、共有は利用者の許可範囲に限る。

## 7. 追加質問の停止条件

質問は、評価項目の評点、情報区分、赤旗判定、融資ルート適合傾向、または推奨アクションを変え得る場合に限る。残る `unknown` が結論・暫定性・優先アクションを実質的に変えないと判断した時点で止める。利用者が追加開示を望まない場合も止め、未開示情報を `unknown` と明示して暫定診断を続けるか、モード選択や必須入力が不足する場合のみ採点不能と説明する。
