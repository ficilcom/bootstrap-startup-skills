# 採用・外注・自動化の比較

仕事または能力ギャップに対し、採用、外注、自動化、延期・中止を同じ意思決定期間・通貨・前提で比較する。金額だけで結論を固定せず、実行条件、品質、機密性、可逆性、社内に残る学習価値を明示して、利用者が選べる比較メモを作る。

## 進め方

1. 提出済みの業務記録、工数、見積、給与レンジ、品質事故、契約条件を先に確認する。対象業務、意思決定期限、単一通貨、比較期間、現状を維持した場合の損失を定義し、事実を `confirmed`、`reported`、`estimated`、`unknown` に分ける。`unknown` をゼロや悲観値に置き換えない。
2. 各選択肢について、仕事量・変動性、戦略的重要性、機密性、品質管理、立ち上がり時間、可逆性、社内学習の価値、管理負荷を同じ尺度で記録する。候補ごとの要件充足、失敗時の責任者、需要または品質の検証条件も示す。
3. [計算モデルとJSON契約](references/calculation-model.md)を読み、匿名化した入力JSONをスキル外に作る。採用は総雇用コスト、外注は契約・管理・切替、自動化は構築・保守・監視・失敗処理を、必ず同じ期間と通貨で含める。延期・中止にも残存義務や再開費用があれば含める。
4. スキルのルートで `python3 scripts/compare_options.py <input.json>` を実行する。不明な費用または定量便益が判断に必要なら、数値順位や回収期間を完成させず、不足入力として報告する。便益は売上、費用回避、損失回避など根拠区分と証拠状態を隣に示す。
5. 結論を変え得る既知の悪化要因だけ、入力の `pessimistic_case` に入れて再計算する。これは `unknown` とは別に表示する。恣意的な精密な係数、未確認の収益、管理工数ゼロを置かない。
6. [比較メモ形式](references/report-format.md)を読み、選択肢ごとの総コスト、定量便益、正味効果、回収期間、悲観ケース、適合条件、リスク、未解決事項を示す。自動出力の金額順位は経済比較に限ることを明記し、質的条件を満たさない候補を「最適」と呼ばない。

## 判断上の制約

- 回収期間は、立ち上がり中のコスト、稼働後の定量便益、比較期間内に回収できない状態を分ける。便益は根拠がある現金・費用・損失回避だけを合計し、能力、ブランド、学習など未価格化の価値は別表示にする。
- 給与だけを採用費用としない。報酬、雇用主負担、採用・オンボーディング、設備、管理、ツール、切替または終了費用の該当項目を確認する。外注の低い単価や自動化の低い月額だけで比較しない。
- 悲観ケースは、根拠のある便益減少・費用増加を明示した感度である。不明な見積、責任分界、セキュリティ要件、法的適合性、品質基準は悲観係数で隠さず `unknown` として解消条件にする。
- 高い機密性、不可逆なデータ移転、品質失敗の影響が大きい業務では、契約、アクセス制御、レビュー、ロールバック、責任者を満たすまで経済性だけで進めない。必要な法務・労務・税務判断は、現在の一次情報または適切な専門家に確認する。

## 権限

採用応募・面接、候補者や委託先への連絡、契約締結、発注、支払、ツール購入、アカウント作成、データ共有、実装・導入は実行しない。各外部変更の直前に、対象、金額または条件、相手、不可逆性を示して利用者の明示的な承認を得る。この比較スキルの利用承認は、それらの実行承認ではない。
